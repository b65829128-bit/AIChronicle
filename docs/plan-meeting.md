# 会晤：可见的结构化交涉

状态：会晤首版已于 2026-11-04 经用户测试并提交；其后接入决斗等延后事项，当前验证与待复测见 `plan-duel.md`。net472 构建、纯逻辑回归、史书/会晤 Web 回归与仓库健康检查通过。原版交易和婚配入口保留；新会晤提供 AI 议价，不接管原版成交判断。

## 契约

已实现的组合扩展（已确认）：双方报价加入可组合行动条款，首批为释放指定俘虏、家族加入/叛逃至指定王国；保留财物和婚配。滚动使用独立容器目标位置累加与短时间插值，不再二次衰减宿主像素量；刷新保持阅读位置。

会晤宿主单独设置 `wheelPixelsPerNotch=96`：±120 为一格，触控板小 delta 按比例，不随输入事件频率变慢；页面以 38ms 时间常数插值并在反向输入时立即转向。聊天/交涉/下拉各自滚动，其他 CEF 页仍用原映射。

工作区 Grid 行固定为 `minmax(0,1fr)`，左侧事项列设 `min-height:0`，nav 独立滚动，左栏标题/边缘的滚轮也转给 nav，避免留白死区和新增长说明把三栏撑出 800px 视口。事项刷新保留 nav 的阅读位置；预览只原位更新摘要，保持已打开下拉和滚动动画；聊天自动追尾识别正在上翻的滚轮目标，不覆盖阅读意图。实际 CSS 布局另用本机 Chrome 回归，DOM 桩不作为布局正确的证据。

`node tests/web/meeting-browser.test.mjs` 用已安装的 Chrome（可设 CHROME_BIN）执行真实 HTML/CSS/产品脚本，覆盖五项长说明的三栏约束、左栏滚到最后事项、右栏与 70 项下拉独立滚动、延迟预览不销毁下拉，以及流式刷新期间上翻聊天。无需新依赖；CI 继续运行不依赖浏览器的 DOM 桩回归。

浏览器回归通过本地调试管道使用真实时钟和绘制帧，并将视口显式设为 1360×800；不用 dump-dom 的虚拟时间验证 RAF 动画，以免跳过绘制帧产生误报。

组合条款协议：`otherOffer/yourOffer` 除 gold/items 外包含 `actions:[{typeId,parameters}]`，由对应报价方执行。新工具 schema 要求完整 actions（无行动用空数组）；运行时读取仍接受原有省略 actions 的内存请求，未修改存档/往来日志格式。每方最多 8 项行动，目标、数量和资源冲突在提交/还价/接受/执行前检查。婚配与同一家族换国属于冲突条款，须分开交涉。

`MeetingClauses.Register(IMeetingClauseHandler)` 注册可组合条款；与顶层事项 `MeetingRegistry` 分工。批执行器全量预检，按释放俘虏→婚配→换国排序，具体对象在交付财物前绑定。所有前置条件仍成立才执行；若首项生效前失败，恢复财物；若已有不可撤销效果后失败，记录“部分履行”、实际已执行/未完成事项，保留已交付财物，不假称回滚、不自动重试。

原 `change_kingdom` 的加入/叛逃模式在会晤内改走行动条款；禅位/离国/雇佣兵等其他原有模式不受本轮影响。条款内双方家族领袖都可明确同意转换本家族阵营；M 页不提供快捷换国、旧工具仍拒绝代替玩家直接操作的规则保持。

- 普通领主对话与投降谈判的模组入口进入会晤；CEF 不可用或非领主时回退现有原生聊天。
- 三栏：事项清单、现有往来聊天、当前交涉卡。文本输入使用原生输入框；网页只 dispatch。
- 首版实装物品/金币双向交易、家族婚配（包含玩家本人、可附双向财物或完全无条件）；新增决斗通过双胜负分支与显式开始扩展。实机已能完成野外决斗，最新返回流程修复及其他场景仍待复测，详见 `plan-duel.md`。
- 原版交易/婚配对话不删除、不打补丁。交易物品取双方有权控制的部队物资，保留品质修饰符，不动穿戴装备；没有部队物资控制权时仍可谈金币/婚配。
- 玩家与 AI 使用同一张交涉单：提案、还价、接受、拒绝、撤回、成交/失败。AI 可主动发起。明确版本与提议者；任何改价清除先前接受，双方接受同一版本才成交。
- 各次修改包含会话、请求编号与版本校验；结束/关闭会晤、切档后旧回调失效。LLM 工具上下文按 AsyncLocal 隔离，并随主线程分发捕获/恢复。
- 单次只允许一张未结束交涉单。玩家提交即接受自己提出的条件，AI 原价接受可使即时事项成交，延后事项进入待开始；AI 还价须由玩家接受。提交、还价、接受及开始前均校验。
- 角色只代表本人财物；部队物资只有领队可处置。婚配须对方家族领袖；玩家只能代表本家族（自身婚配或家族领袖安排成员）。双方成人、存活、可婚、非近亲等由当前 MarriageModel 校验，婚后家族归属公开显示。
- 所有金币/物品调动在主线程统一提交；执行前完整预检，尚无不可撤销变化时失败补偿资产，已有不可撤销变化时如实记录部分履行；婚配调用原版 MarriageAction 并检查实际效果，禁止自动重试已生效的动作。
- 会晤中金币/物品相关的旧直接转移工具由交涉工具替代，避免绕开当前条款；其他身份能力保持既有规则。会晤工具在后台、书信、秘书等场景不开放。
- 会晤只保存当前遭遇内存状态，沿用 chat_logs 记录叙事与成交结果，并写 NPC 本人的结果日记；关闭时也写清“撤回、未成交”，避免下次把旧提议误当作仍在等待兑现的约定。普通会晤无新增存档字段，不向其他 NPC 暴露私人交涉。决斗另有兼容旧存档的独立计数键和已开始任务的跨场景生命周期。

## 扩展位置

家族成员加入/自立新增 `join_clan`、`found_clan` 即时事项：双方本人决策，夫妻与同族未成年子女随迁，原部队和个人金币保留，资助可为零，原族长仅静默知悉。客观资格与执行边界见 `plan-clan-departure.md`；无需原族长或远方国王审批，不因忠诚/好感/敌我关系隐藏入口。

`IMeetingAction` 提供类型 ID、名称/说明、可用条件、参数字段、条款校验、效果执行、生效检查、摘要预览和成功记录钩子；`MeetingRegistry.Register` 为唯一注册点。金币/物品报价、版本和接受状态、通用 AI 工具、CEF 表单和成交入口共用，核心服务不按事项 ID 分支。

新增动作：实现 handler → 注册 → 补执行/校验测试及文档。等待外部结果的事项实现 `IMeetingDeferredAction`；`outcomeSlots` 定义结果，UI 自动绘制各分支双向报价，AI `terms.outcomes` 使用同一结构，顶层即时报价保持为空。双方接受后 Ready，显式开始后 Running；已开始请求关闭会晤仍可由持有者完成一次结算。`IMeetingScopedClause.ActionTypes` 同时约束网页选项与服务端。专有字段由元数据生成，标准下拉/数值/文本字段无需改网页；如新玩法需要特殊控件或异步游戏事件，在 handler/对应适配层扩展。

字段约定：`choice` 提供 `Choices`（精确 ID/显示名）；`number` 提供 `Minimum/Maximum`（以十进制字符串写入 parameters，服务端再次解析）；`text` 使用原生输入。所有字段当前均必填。婚配预览和新事项预览共用 handler.Describe。成交摘要在提交时保存人物/物品名称，避免库存转移或婚后换族后显示技术编号。

## 文件分工

- `Systems/MeetingModels.cs`：纯 DTO、双向报价、参数、字段元数据。
- `Systems/MeetingNegotiation.cs`：纯状态机；所有输入复制，版本、角色和幂等校验。
- `Systems/MeetingRegistry.cs`：动作接口和注册表。
- `Systems/MeetingClauses.cs`、`MeetingClauses.Prisoners.cs`、`MeetingClauses.Allegiance.cs`：双方报价中的可组合行动及注册表，明确实际执行者、目标、资源冲突与原版动作。
- `Systems/MeetingBatch.cs`：纯逻辑多效果预检/排序/补偿/部分履行识别，未生效的失败恢复财物；已有不可撤销效果时如实记录部分履行，禁止退款后再次执行已完成行动。
- `Systems/MeetingActions.cs`：交易/婚配内置 handler。
- `Systems/MeetingAssets.cs`：物资精确标识、财产校验、提交与补偿。
- `Systems/MeetingService.cs`：当前遭遇会话、玩家/AI 共用入口、生命周期。
- `Systems/MeetingPageBuilder.cs`：网页数据和 AI 上下文。
- `Tools/ToolExecutor.Meeting.cs`：查询/提案/回应工具适配。
- `UI/Web/MeetingCefScreen.cs`、`_Module/WebUI/meeting.html/css/js`：CEF 三栏页面和原生输入。
- `_Module/Prompts/meeting_rules.txt`：可热重载的会晤规则，仅使用“你/对方”，不向角色引入“玩家”概念。条款字段 `otherOffer/yourOffer` 分别表示对方提供/你提供，婚配字段 `otherHeroId/yourHeroId` 同理。
- `tests/AIChronicle.Pure.Tests/MeetingTests.cs`、`tests/web/meeting-render.test.mjs`：状态机/参数/报价/界面回传回归。
